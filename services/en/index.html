01 / AI coding agents

Test agents on your team's tasks

For teams trying AI coding agents or planning to adopt them. We examine which tasks to delegate and how to check the code before acceptance.

Pilot

Estimate: 2 working weeks

One team, one repository, and 2–3 agreed tasks: a process review, changes in pull requests, and instructions your team can follow to repeat the work.

  • Discuss your team's tasks
What you receive
Pull requests, an agent task template, verification rules, and a team guide in your repository. The report documents your current process, its constraints, the agent workflow, and recommendations for adoption.
Scope
I review the selected tasks and configure access, spending limits, and checks in your CI. The pilot covers one repository and the agreed tools. Adoption by other teams and platform redesign are separate phases.
What I need from you
Your repository and CI, sample tasks and previous PRs, tests, approved models and tools, and code and data handling requirements. An engineer from your team owns the pilot and takes part in acceptance.
Acceptance criteria
  • The selected tasks pass the agreed functional checks, with changes submitted as pull requests.
  • The checks detect a deliberately introduced, testable defect and block acceptance.
  • Your engineer reproduces the process by following the guide.
  • The report records costs, limitations, and findings to support a decision on further adoption.

02 / Engineering automation

Automate a manual process

Release preparation, change validation, environment setup, or engineering data processing. We choose one recurring process.

Pilot

Estimate: 1–2 working weeks

One process, with up to two integrations into existing systems. Initial execution and failure testing take place in a test environment.

  • Discuss automation
What you receive
An automated process, source code, execution logs, and error diagnostics. For example: validate changes, build an artifact, and prepare it for release. The guide covers maintenance and recovery after a failure.
Scope
I automate one sequence of steps and the agreed exceptions using your APIs and infrastructure. After validating the pilot, we estimate production rollout, system replacements, and ongoing support separately.
What I need from you
The manual steps, typical examples and failures, test data, access to the test environment and APIs, rerun rules, and the expected result of each step. A process owner confirms that the automation works correctly.
Acceptance criteria
  • Success and failure scenarios pass in the agreed test environment.
  • Reruns follow the documented rule, without unexpected duplicate actions.
  • The logs show where and why the process stopped.
  • You run and recover the process using the guide; before-and-after measurements are included in the report.

03 / B2B product

Build a prototype with one integration

You have a specific user and task in mind. Before full development, we test the architecture, a key integration, and one user workflow.

Pilot

Estimate: 3–4 working weeks

One end-to-end user workflow and one key integration, from input data to a result delivered through an API or interface.

  • Discuss your product
What you receive
A working user workflow, source code, a reproducible build, and tests. The documentation records architectural decisions, known limitations, and a plan for further development.
Scope
I implement one agreed sequence: accept a request, process it according to the rules, and return a result. I choose the stack for that task. A full feature set, all user roles, additional integrations, and production operation fall outside the pilot.
What I need from you
A description of the user and task, sample data, integration contracts, and infrastructure constraints. A product owner needs to be available for timely decisions. Before development, we agree on workload volumes, response times, access requirements, and verification scenarios.
Acceptance criteria
  • The end-to-end workflow works with the agreed data, including error handling.
  • Performance is checked in the agreed test environment if that check is part of the pilot.
  • You can build and run the solution by following the guide.
  • The demonstration, source code, and report let you verify the workflow and its remaining limitations.

Before work starts

Price, access, and handover

How are the price and timeline set?

The timelines above are estimates for the stated scopes. After a short project brief, we agree on deliverables, acceptance criteria, timeline, price, and spending limits for tools and infrastructure. We discuss additional tasks before starting them.

What about data and access?

We agree on permitted data, models, and tools, where the work runs, and who accepts the results. I start once the terms are agreed and the required access is in place.

What happens after the pilot?

I demonstrate the agreed scenarios and hand over the code, guides, and report. We use the findings to decide what comes next and agree on any further work separately.
